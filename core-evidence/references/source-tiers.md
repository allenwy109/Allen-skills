# 来源分级与独立性

部分思路借鉴 zerox-deep-research 与 zerox-due-diligence 的信源评估（ZeroxZhang/zerox-skills），按本系统需要改写。

本文件是来源评价规则的唯一出处；字段的枚举值只在 `tools/lib/schema/ledger.schema.json` 里定义，这里只写含义和规则。

## 四件不同的事

等级、访问程度、核实状态、置信度是四件不同的事，各用一个字段，不能互相推导：

| 字段 | 回答什么 | 取值 |
|---|---|---|
| `tier` | 事实从哪来 | `primary` 一手 / `secondary` 二手 / `tertiary` 三手 |
| `grade` | 材料本身可靠到什么程度 | `S` / `A` / `B` / `C` / `D`，见下表 |
| `access` | 我们实际读到了多少 | `full`、`partial`、`summary`、`snippet_only`、`metadata_only`、`blocked`、`unreadable` |
| `origin` | 出处 | `user` 用户提供 / `web` 联网查证 / `model_memory` 模型记忆 / `derived` 推算 |

主张的核实状态（`verification`）和置信度（`confidence`）记在主张上，见 `../SKILL.md` 第 6 节。

## 层级：按事实看，不按载体看

- 一手：事实的原始产生者或当事方，能支撑关键结论。
- 二手：对一手的整理和评价，用来发现线索、交叉印证、提供背景。
- 三手：百科、聚合站、软文、内容农场、榜单，只用来找词和找线索。

一篇博客引用了财报原文并给出页码，就这条事实而言接近一手。

## 等级

| 等级 | 含义 | 例子 | 能支撑什么 |
|---|---|---|---|
| S | 官方与法定 | 工商登记、监管和司法文件、交易所与法定披露、经核验的审计报告、标准与法规原文 | 关键事实与关键结论 |
| A | 方法透明、可以复核 | 统计局数据、同行评审论文、附数据和方法的研究与基准测试 | 关键事实与关键结论 |
| B | 可信但有局限 | 券商研究、商业数据库、主流媒体深度报道、方法不完全透明的机构报告 | 交叉印证、背景；可支撑非关键结论 |
| C | 有立场或宣传性质 | 企业宣传、管理层自述、一般报道、访谈、无第三方验证的厂商白皮书 | 只当线索 |
| D | 匿名或无法追溯 | 匿名帖子、引用链断裂的转述 | 只当线索 |

等级只是起点，可以按具体材料调整，调整时在 `grade_reason` 里写明理由。等级评的是材料本身，不是观点：C 级材料里的事实也可能是对的，只是不能单独支撑关键结论。

旧版只有 A/B/C 三级，对应关系是：旧 A → S（官方、法定）或 A（方法透明）；旧 B → B；旧 C → C（有立场）或 D（匿名）。

## 访问程度

- `access` 不是 `full` 或 `partial` 的来源，不能单独支撑关键结论：搜索摘要只能证明结果页上出现过这句话，只读了首页不能算读了其他页面。
- `metadata_only`、`blocked`、`unreadable` 的来源不能形成证据（`ledger.py check` 会拦下）。
- 遇到付费墙、登录或验证码就停，如实记成 `blocked` 或 `metadata_only`，不绕过。

## 独立性

- 关键结论依赖的主张必须达到“已核实”（判定标准见 `../SKILL.md` 第 6 节）：至少 2 个相互独立的合格来源（grade 为 S、A、B 且 access 为 full 或 partial），或 1 个 tier 为 primary、grade 为 S 或 A 的来源。
- 多篇文章转引同一个源头只算 1 个。在 `origin_group` 里标记同源，在 `upstream_source_id` 里记录转引链；不同媒体写出几乎相同的数字和措辞，多半同源。
- “独立”指证据来源独立，不是作者不同：同一家机构的两份材料不算独立。

## 每个来源查四项

1. 作者和机构是谁，利益立场是什么。
2. 发布日期和数据日期（见 `freshness.md`）。日期不确定时，`published` 留空，在 `published_precision` 里写 `unknown`，不要编日期。
3. 有没有利益冲突：厂商自评、赞助研究、广告、返佣。有冲突不等于不可信，但要记在 `conflict_of_interest` 里。
4. 数据怎么来的：样本多大、自报还是第三方统计、是否修订过。

## 数字口径

数字对不上时，先查口径，再判断谁错：

| 项 | 要问的 |
|---|---|
| 口径 | 统计的是什么：出货量 / 销量 / 激活量 / 付费用户 / 月活 |
| 单位 | 币种、是否含税、万 / 亿 |
| 时间 | 财年还是自然年，期末值还是平均值 |
| 范围 | 集团还是子公司（合并 / 单体 / 分部 / 品牌），全国还是部分地区 |

口径不同的数字不能直接比较或相除；必须比较时，写明换算假设。
