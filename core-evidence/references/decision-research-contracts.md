# 决策研究判断指南

用于 L2/L3 中会改变结论的需求、竞争、定价和方法判断。结构字段以 `<运行时>/tools/lib/schema/decision-research.schema.json` 为准；判断记录写入 `03_evidence/decision-research.json`，证据只引用统一证据账的 claim ID，不复制证据。

## 需求：从现象到购买

每条重要痛点沿同一条链记录：**细分客户 → 触发情境 → 当前权宜办法 → 可观察后果 → 购买或切换信号 → 证据边界**。购买或切换信号优先用已发生的预算、采购、试用转付费、替换、续约或明确放弃旧办法；搜索量、讨论热度、投诉和 TAM 只能证明现象或关注，不能单独证明发生率、严重度或付费意愿。

例：三位访谈对象描述月末手工对账，能支持“该现象存在”；没有代表性样本就不能推出“多数客户都有”。供应商案例中的成交可作为线索，但不能独立推出普遍购买意愿。每条痛点同时记录支持主张、反面主张或对抗检索、置信度和仍需验证的边界。

## 竞争：覆盖购买决定的五层替代

竞争不是公司名单。按买方解决同一问题时实际可选的五层记录：

- direct（直接）：相似产品服务相似客户；
- indirect（间接）：不同产品或服务完成同一任务；
- diy（自建）：内部系统、人工、表格或自行组合；
- adjacent（相邻）：有客户、渠道、数据或能力可进入的参与者；
- do_nothing（不行动）：延后、不购买、忍受损失或维持现状。

比较标准从购买决定出发，例如总成本、切换成本、部署周期、风险、可验证效果、采购权限和供应商可信度。每层至少有一个有证据的选项；确实不适用时记录 `not_applicable` 及其 claim ref，不能留空。市场上列出三家直接竞品不等于完成竞争分析。

## 方法：先问覆盖问题，再决定是否使用

这些是“考虑过”的覆盖问题，**不强制全用**，更禁止每个任务套完所有框架：

| 方法 | 只有在它能回答这些问题且前提成立时使用 | 必须留下的实际产出 |
|---|---|---|
| 3C | 客户选择什么、企业凭什么交付、竞争者如何回应？ | 三方证据对照与差距判断 |
| 五力 / 替代品 | 利润被谁拿走，替代和不行动如何约束价格？ | 力量强弱的证据及决策含义 |
| STP | 可区分、可触达、可服务的细分是否存在，目标为何优先？ | 细分依据、取舍和定位命题 |
| 定价三角 | 客户价值、成本底线、替代价格分别是什么？ | 价格区间或不可定价的缺口 |
| 客户旅程 | 哪个具体触点产生摩擦并改变行为？ | 有证据的触点、摩擦和机会 |
| KSF / 能力差距 | 赢得购买所需能力是什么，当前差距能否补齐？ | KSF 证据、能力现状和缺口 |

`02_method-plan.md` 不能只列方法名。每个方法记录前提状态、实际产出；若前提不齐或降级，写降级理由。没有执行产出的方法不得出现在结论中充当分析依据。

## 关键主张与高风险说法

把会改变建议、排序、估值、进入或停止决定的主张列入 critical_claim_refs。所有被合同引用的主张都写 claim_risk_assessments：风险类型、是否缩窄、是否限制置信度，以及 issuer_source_ids。issuer_source_ids 只列与该主张有支持关系、且身份确为发行方、被评企业或卖方的 source ID；独立买方企业即使 source_type 为 company，也不属于 issuer。关键主张必须有可解析的支持证据，并有反驳关系或绑定该 claim ID 的对抗检索。

对发生率、付费意愿、竞争强度、因果和监管义务从严处理。若支持只来自发行方、被评企业或卖方材料，不得写成总体事实；只有缩窄到“该发布方报告/该样本显示”且置信度为低时才可保留。监管指南、征求意见稿和行业倡议不能写成法律义务，除非法规原文和适用范围直接支持。

结构完整性、claim 引用解析和发行方单一来源限制由 `research_quality.py` 机械检查；本指南用于决定什么是重要、什么算证据及结论能说多强。
