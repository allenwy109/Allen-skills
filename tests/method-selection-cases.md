# 选方法测试题

用来检查 core-method-select 和三个方法库的选法表是否把方法选对。每次改选法表、卡片或 core-method-select 后，挑几道（或全部）重跑。

## 怎么跑

1. 新开一个会话，确认本仓库的 skill 已安装（`./install.sh`）。
2. 把“题目”原样发给 Claude Code 或 Codex，并加一句：“只做到选方法这一步，输出方法计划（02_method-plan 的格式），不用做分析。”
3. 对照“期望”打分：
   - **选对**：首选方法一致，或选了期望里列出的可接受方法。
   - **前提处理对**：期望里写了“前提不满足”的题，必须识别出来，并且补信息或降级，而不是硬用。
   - **跨库对**：期望里写了跨库的题，必须用到对应方法库。
4. 把结果记到本文件末尾的“记录”表里。

## 题目

| 编号 | 题目 | 期望的方法 | 考点 |
|---|---|---|---|
| C1 | 我们公司去年利润掉了 30%，收入只降了 5%，帮我看看问题出在哪。（用户附了两年的分产品收入和成本表） | 利润树；定位到成本侧后可接价值链 | 有数据、能用公式拆，优先公式法 |
| C2 | 我们在考虑砍掉几条产品线，但手上没有市场份额数据，只有各产品线的收入和毛利。 | 不能直接用 BCG（缺相对份额）；降级为按利润贡献排序 + 定性 KSF 对比，或先用 core-evidence 查份额 | 前提不满足时补信息或降级 |
| C3 | 新能源汽车充电桩这个行业，2026 年还值不值得进？ | 五力（补 PEST 看政策和技术变化）；关键数据要联网核实 | 时效性信息必须核实 |
| C4 | 战略都定了，各部门就是执行不下去，问题在哪？ | 7S（lib-consulting）诊断；推进部分跨到 lib-management 的变革管理 | 跨库：诊断和推进分开 |
| M1 | 生产线上同一个尺寸超差问题，三个月里客户投诉了三次。 | 8D（先止损再根治），D4 根因用鱼骨图 + 5WHY | 严重客诉 → 8D，而不是只用 PDCA |
| M2 | 我们是一个 6 人的研发小组，在做一个全新产品，想定下季度目标。 | OKR（探索型、自驱团队），每条 KR 过 SMART | 探索型 vs 重复型 |
| M3 | 项目里四个部门配合，总是互相推诿，没人对结果负责。 | RACI | 多方协作、职责不清 |
| M4 | 我们想做一次复盘，但老板的意思是要找出谁的责任。 | 指出“追责不是复盘”，建议 GRAI 并说明前提不满足的风险，或改为问题调查 | 前提（目的不是追责）不满足 |
| P1 | 我每天事情很多，忙到很晚，但重要的事一直没进展。 | 80/20 + 要事第一；或四象限 | 对症：优先级问题 |
| P2 | 我知道该写论文了，但一打开电脑就刷手机，拖了两周。 | 吃青蛙（拆出 5 分钟第一步）+ 番茄工作法 | 对症：拖延不是优先级问题 |
| P3 | 我在纠结要不要换工作，两个 offer 各有好坏。 | 加权决策矩阵；得分接近时补 10/10/10 | 决策类 |
| X1 | 帮我看看这份 BP：说市场规模 500 亿、年增 30%，没有直接竞争对手。（附 BP） | 先拆说法、核实；市场规模估算交叉验证；五力或 3C 看竞争；“没有竞争对手”要核查 | BP 场景：核实先于判断 |
