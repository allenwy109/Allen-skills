# 上市关联与研报（模块 18）

## 1. 什么时候触发

任一条：目标本身在交易所上市（含不同上市地或证券类别）；目标是上市公司直接、间接或协议控制的子公司；品牌、分支、业务单元能映射到上市主体或其控制的企业。Quick、Standard、Deep 都必须执行。

`diligence sync` 从目标沿"在基准日生效、已核实、不是拟议"的 control、brand_of、branch_of 边向上追溯（区间左闭右开）。共同控制默认不触发、只给警告；需要时把 project.joint_control_triggers 设为 true。身份未锁定、有主体上市状态未知、有未核实的生效边、控制链没核对时，追溯结果是 pending。挂牌、发债、拟上市、已退市企业不自动等同上市公司。

实体映射要记录：目标法定名、注册号、业务名、曾用名；上市主体、交易所、代码、类别；控制链、比例、依据、证据、生效日；基准日是否仍受控（拟收购、已出售、分拆、重组、出表）。目标本身上市且有上市控股股东时，两者分别建档。

## 2. 必读类别

| 类别 | 含义 | 何时必需 |
|---|---|---|
| official_annual | 最新年报 | 总是 |
| official_interim | 最新中期或季度报告 | 总是；只有它可以在制度不适用或尚无该期时豁免（project.category_exemptions，写理由并附证据） |
| company_update | 最新公司跟踪、业绩或事件点评（子公司没有单独覆盖时找母公司的） | 总是 |
| company_deep | 最新深度、首次覆盖、业务专题 | 总是 |
| industry | 最新细分行业报告 | 总是 |
| official_event、event_update | 重大事件公告及更正、事件后研究 | 有绑定到该上市主体或目标的事件时（project.events） |
| peer | 可比或上下游研究 | project.peer_required=true 时 |

- 券商研报和官方披露都必须出现在研究设计里，不能互相替代；券商公司研报、公司自己发的年报公告、评级机构信用报告分别登记。
- 每个会改变决策的核心业务，尽量覆盖两家独立机构以识别分歧；只有一家时记录限制（不是硬配额）。

## 3. "最新"的定义

- 从基准日往前，按类别分别排序；公司跟踪和事件研究按 90 天 → 180 天 → 12 个月 → 更早的顺序找；深度和行业框架可以回溯更久，但要标注历史用途。窗口只是检索顺序，不是合格线。
- 报告日期早于最近的重大事件时，必须补查事件后的报告；没找到就记"未发现覆盖该事件的报告"，用官方资料自行补充，保留缺口。
- 首发日、修订日、平台收录日、上传日、访问日分开；报告日要等于来源的发布日或修订日，不能按上传日把旧报告当新报告。数据截止日、预测期、估值基准日分别记录。
- 同名同日不同版本用 supersedes_id（要同机构、同覆盖主体、日期不早于被替代的报告）。
- 三个"最新"指针：最新发现、最新全文、最新已读，同一日期的多份报告全部列出（指针是数组），并与研报表的反向数组双向一致——`diligence sync` 自动维护。
- 交付前复查一次，写 project.last_refresh_at。只能说"截至某日在列明渠道中发现的最新报告"。

## 4. 检索与获取

- 渠道优先级：原始机构 → 用户授权终端 → 合法公开平台。
- 关键词：名称、简称、代码 + 深度、首次覆盖、点评；母公司 + 子公司、品牌、分部；细分行业 + 深度、供需、价格；重大事件 + 名称 + 研报；海外加英文词（equity research、initiation、earnings update、sector report、industry outlook），配合 site: 和 filetype:pdf，使用真实年份。`diligence plan` 会生成这些任务。
- 步骤：建候选目录，按相关性、时间、事件覆盖、原始性、独立性挑选 → 打开原页核对标题、机构、作者、日期、证券、页数 → 有权限才保存原文件 → 读全文、图表、脚注、假设、风险提示、利益披露 → 拿不到全文时尝试公开版、原机构页、授权渠道或请用户提供，并记录尝试 → 旧全文只能作补充。
- 获取状态（access）和阅读状态（reading）分开记；只有全文才能标 analyzed。没找到报告时只建覆盖行和缺口，不建报告记录。

## 5. 每份报告提取什么

身份信息、数据截止日、预测期、估值日、核心结论和假设、业务拆分、预测及与前次的变动原因、估值方法、目标价和评级（只在报告实际提供时）、风险、利益冲突、子公司相关段落及适用范围、哪些被官方支持哪些是券商估计、对本项目结论的影响。正文引用时写成"某机构某日基于某假设预计"。

**子公司专项核验**：控制和合并范围、子公司对集团的收入利润资产贡献、内部交易抵销、资金归集、担保、商誉和业绩承诺、剥离计划、资质和合同归属、分离后能否独立经营。

**观点比较**：机构、日期、实际或预测口径、假设、分歧、支持和反对证据、采信理由。同一公告的数字被多家引用仍只算一个事实来源；不平均不同口径的数字；把机构观点拆成可验证的假设与独立证据比对（"多家结论一致"不等于假设成立）。一般公司研究不强制给目标价或评级。

## 6. 研报门槛（research_gate）

它只表示资料覆盖，不代表研究范围完成。

- 每个类别：同一最新日期的全部候选报告（去掉被替代版本）都是全文、已读、直接相关，事件类覆盖了所有事件日期，检索状态为 found 且有检索记录和最新性复查时间，事件覆盖为 covered 或不适用，关联缺口已关闭 → complete；有任一份已读全文 → partial；否则 incomplete。
- 整体：没有必需项时，追溯 pending 为 incomplete，否则 not_applicable；全部类别 complete 且追溯不是 pending → complete；有任一 complete 或 partial → partial；否则 incomplete。门槛按实际检索和阅读记录判断，不依赖"是否联网"的标志——用户离线提供了全部全文且已读完，同样可以完成。
- 硬规则：已知有更新的相关报告但没拿到或没读，不能标完成；不能以"旧报告够用"豁免；因相关性不足排除要写理由（relevance=excluded + exclusion_reason），不能只因难拿到就排除；未完成的类别必须挂一个开放缺口；没有研报覆盖时不能写"已完成最新研报研究"；资料不足时仍交付结果，首页说明限制，列出报告名、机构、日期、障碍、补齐路径；缺研报不代表公司风险高。
