# 交付前质检

## 1. 自动检查（`research check`）

任务文件夹和研究包用同一套规则：

- 快照：只允许一级 .md；能解析；ID 合规、不重复、与文件名一致；必填字段齐全；枚举合法；每个原件存在且哈希一致；完整度为全文或部分时正文不能为空；没有未登记的原件；至少一个快照。
- 来源索引：任务文件夹核对证据账（快照头与 sources 表一致由 ledger check 负责）；研究包核对 sources.md（按表头名解析，完整度、采集方式、层级、等级、标题与快照一致，本地文件列含快照路径）。
- 证据：来源存在；有定位；摘录按 `[...]` 切成片段，归一化后必须按原顺序逐字出现在快照正文里。零覆盖算失败。
- 检索日志：每条有查询原文；search_status 与实际检索双向一致；弱检查（警告）：时间格式、工具名、弃用原因、"打开并存档"的 ID 有快照。
- 数据：见 data-package.md（状态一致、字典、公共字段、空表、记录类型、缺失不为 0、提取层与整理层互斥、method 在 analysis/、孤立表、血缘存在、无环、有值不依赖缺失）。
- 报告：有参考来源节；条目格式、链接与快照对应；正文引用都有条目（支持 `[1,3]`、`[1-3]`，排除代码和年份方括号）；没被引用的条目警告；数据关联指向真实记录；数据可用时至少有一处数据关联。
- 决策研究：L2/L3 且需求、竞争或定价重要时有 `03_evidence/decision-research.json`；按 `../core-evidence/references/decision-research-contracts.md` 判断内容是否充分，并在综合前运行 `python3 <运行时>/tools/research_quality.py check <任务文件夹>`。
- 弱检查（警告）：影响结论的主张只有 1 个独立来源且没有一手 S/A 级来源；支撑来源都不是完整正文；单文件超过 50MB、总体积超过 500MB。
- 研究包 `--final`：复核记录齐全、指纹未过期；README 统计标记各一个；manifest 覆盖全部文件且哈希一致；checks.json 为 FINALIZED 且指纹一致。

**自动检查通过不等于人工复核通过**；是否可交付以 `--final` 为准，不手填通过状态。

## 2. 人工清单（7 组）

- **问题是否被回答**：执行摘要第一段就能读到答案；每个子问题都回答了或列进未解问题；交付物符合简报。
- **事实与引用**：数字、日期、名称逐项与来源一致，尤其是手写的数字；非常识性事实都有引用（"常识"不是免检通道）；关键结论逐条回查快照原文；没把相关夸大成因果；没有编造。
- **证据质量**：关键结论有一手或权威来源；循环引用已排除；口径已核对，口径不同的数字没被直接比较；做过对抗检验；低于 partial 的来源没有单独支撑关键结论。
- **决策质量**：痛点已从现象走到购买或切换信号；竞争覆盖直接、间接、自建、相邻和不行动；方法有前提状态与实际产出，而非只列方法名。
- **平衡与诚实**：对照类型骨架扫一遍有无遗漏维度；分歧如实呈现，包括与自己判断相反的证据；事实、推断、推测分开写，置信度给了理由；标了"截至"日期，用的是最新可得信息；已采纳的假设逐条复述进「方法与局限」。
- **数据**：简报的每项数据需求已获得，或缺口及影响已披露；关键数据已进数据集，报告与记录一致（不能只关联一条记录就宣称全部覆盖）；提取值与原件的页码、表、单元格逐项一致，工具摘要没有被误标为原文；行粒度、口径、字典足以支持复用；冲突值分别保留，选取和转换理由可复核，多来源是否其实同源；派生数据实际复跑或独立代入过；定性编码的标准和歧义写清楚。
- **包完整性**：元数据齐全，没有孤立文件，无法存档的来源写明原因；raw 未被事后改动；README 统计由脚本生成；内部资料已标注，机密没进公开查询；复核已登记并绑定指纹。
- **高风险领域**：局限已注明，列出需向专业人士确认的问题。

## 3. 红队审稿

全新上下文，只读研究包，不读对话、不接受作者的口头说明。从报告出发问 6 个问题：引用是否真的支撑结论？哪些表述说过头了？哪条结论只有一条弱来源撑着？有没有结论在快照里找不到出处？反面证据是否被公平呈现？关键数据能否追到原始值，派生过程能否复算？输出按严重度排序的问题清单（结论 → 问题 → 证据位置），不客套。问题改完才能交付。提示词见 `../core-review/references/reviewer-prompts.md`。

## 4. 复核记录

复核人把结论写进证据账 reviews 表：type=research_review，reviewer 写实际执行复核的人或子代理，digest 写 `research seal --prepare` 打印的内容指纹，checks 写 4 项，每项 `{passed, evidence}`：

- questions_answered：逐项对照简报，回答或明确缺口的位置；
- evidence_support：关键结论到原文的实际核验路径、来源独立性、反证；
- data_semantics：关键数据覆盖、原始值核对、口径可比性、计算复跑或独立代入结果；无数据时写不可得或不适用的理由；
- limitations：假设、时效、不可得数据、无法存档等限制的披露位置。

## 5. 自评等级（逐级累加，只报实际达到的最高级）

1. **可追溯**：关键结论能一路追到快照原文；自动检查零错误；人工复核完成；`--final` 通过（L2 不封包时，以任务文件夹检查零错误代替）。
2. **可复现**：在上一级基础上，计算已实际复跑或独立代入验证，检索记录完整（没检索要披露原因）。
3. **经对抗**：在上一级基础上，主要结论做过反面检索，并经过独立红队审稿。
4. **可决策**：在上一级基础上，直接回答了核心问题，有"对决策意味着什么"，假设与局限足以支撑决策。

达不到就报低一级，并在「未解问题」里写明差在哪里。
