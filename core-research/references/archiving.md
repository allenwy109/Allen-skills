# 存档

## 采集方式

| 优先级 | capture_method | 用法 |
|---|---|---|
| 1 | script | `research capture`：下载原始字节、抽正文、逐个原件算哈希。能执行代码时必须先用这个 |
| 2 | browser | `research capture --browser`：动态页面、图表、社媒；经本机已开的 Chrome 只读打开，存 HTML 和整页截图 |
| 3 | fetch_tool | 模型逐字转写，不得改写、概括、补全；太长时至少保存相关段落及上下文，删节标 [...]，access 标 partial |
| 4 | snippet | 只有搜索摘要（access=snippet_only），日志里说明为何打不开 |
| 5 | metadata_only | 付费墙、登录墙、已失效（脚本确认拦截时自动登记为这一种） |

降级：脚本被拒（401、403、429、超时）时可以改用浏览器正常访问；遇到付费墙、登录、验证码就停，按 metadata_only 处理，可以查已有的存档记 archive_url。

## `research capture` 做了什么

- 原件存 `03_evidence/raw/files/`（用户材料 U 前缀存 `raw/user/`），快照存 `raw/sources/<ID>-<slug>.md`，在 sources 表登记，每个原件单独记 sha256。
- 编码依次看 HTTP 头、HTML 的 meta、BOM，再试 UTF-8 和 GB18030（覆盖 GBK）。
- 自动抽取标题、作者、发布日期作为候选值（命令行参数优先），并记录 Content-Type 和主要响应头。
- 429、5xx 和网络错误按 1、2、4 秒退避重试；`--respect-robots` 遵守 robots.txt。
- 付费墙和验证码只在可见正文上判断一次：命中标记且正文很短，或命中多个标记且正文不长才算拦截（一篇讨论付费墙的长文不会被误拦，脚本里的字样也不算）。
- PDF 逐页抽取并加 `<!-- p.N -->` 页码；正文超过上限时截断并标 partial；二进制不硬转文字。
- 超过 50MB 不下载，只登记链接和大小。
- 退出码：0 成功；2 访问受限、超限或网络问题（付费墙和超限也会登记一条 metadata_only 来源）；3 参数或状态错误（ID 已存在、slug 不合规、文件不存在）。

## 各类来源

| 来源 | 首选 | 退路 | 快照要点 |
|---|---|---|---|
| 网页 | script | 浏览器 | 记 final_url |
| PDF | script | 浏览器打印 | 页码标记 |
| 数据集 | script 原样下载 | — | 原件进 raw/files，提取的表进 data |
| 官方文件、标准 | script | — | 条文号写进定位，注意修订版本 |
| 社媒 | 浏览器截图 | 逐字转写 + partial | 记发布时间、作者、互动数据的时点 |
| 音视频 | 官方文字稿 | 逐字转写 | 时间戳，注明转写来源 |
| 动态页 | 浏览器 | 抓取工具取静态文本 | access_note 写"动态渲染" |
| 付费墙 | — | — | metadata_only，查已有存档记 archive_url |

**用户材料**：先用 core-intake 处理（原件副本、快照、登记）。二进制无法抽正文时只保留元数据和原件，不伪造正文；文件过大或用户不希望复制时只登记路径和哈希。

## 定位与命名

- 定位要让人几秒内找到原文：`§3.2 第 4 段`、`p.12 表 2`、`00:14:32`、`回复 #2453 第 2 段`。
- 来源 ID 是研究线代号加三位序号（M001、A003）；文件名 `<ID>-<slug>`（小写英文或拼音，≤40 字符）；同一来源的多个文件共用前缀。

## 快照

元数据头（采集时写入、之后不可改，sources 表的同名字段要与之一致，`ledger check` 会核对）+ 正文。正文保留标题层级、列表、表格；PDF 有页码标记；删节标 `[...]`。研究包里的快照由封包脚本补齐评价字段（tier、grade、作者、发布日期、利益冲突等），任务文件夹里的原快照不动。
