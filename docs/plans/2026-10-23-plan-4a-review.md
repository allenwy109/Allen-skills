## 验证方式

- **先跑通再写计划**：代码先在临时副本里写好、跑通。
- **变异检查**：去掉"尚未经过成品审查"规则，4 个失败；不再拦截裸数字，2 个失败。
- **端到端测试**：中文图表实际出图；不平的瀑布图、裸数字都被拦下。
- **实际看图**：成品审查员角度看 PNG，中文标题、单位、来源完整；标题"两年增长近八成"与数据相符（1800 → 3200，约 78%）。
- **对比验证**：用 soffice 包装脚本时，OCR 能读出中文标题；不用时，标题整段消失。

## 开发中发现并解决的问题

| 问题 | 处理 |
|---|---|
| thinkcell 导出 PNG 时中文消失（直接调用默认配置的 soffice） | `tools/bin/soffice` 包装脚本，出图时放在 PATH 最前面 |
| tc_validate 的致命问题级别是 `fatal`，我们写成了 `fail`，导致不平的瀑布图没被拦下 | 同时按 `fatal` 级别和"不能做"结论判断；端到端测试覆盖 |
| 重新登记时显式传 `reviewer=None`，没有沿用原有审查结论 | None 与没传同样处理 |
