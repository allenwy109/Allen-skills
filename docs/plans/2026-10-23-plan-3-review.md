# 计划 3（材料接收）审查记录

## 执行方式

用户要求本会话不使用子代理，以下验证都由执行者完成，**未经独立审查**：

1. **先跑通再写计划**：代码先在临时副本里写好、跑通。
2. **端到端测试**：测试材料现场生成，内容虚构，覆盖文字版 PDF、扫描版 PDF、Word、带备注和表格的 PPT、有整页图片的 PPT、加密 PDF、损坏文件、老格式 .doc。
3. **变异检查**：关掉 PDF 的 OCR 后，扫描件和汇总两个测试失败。
4. **跳过逻辑检查**：缺工具时默认跳过 11 个端到端测试；设置 `ALLEN_REQUIRE_TOOLS=1` 时这 11 个直接失败。
5. **实际看图**：确认修复前页面图片里没有中文，修复后中文完整，OCR 识别正确。

## 开发中发现并解决的问题

| 问题 | 原因 | 处理 |
|---|---|---|
| Word、PPT 转出的 PDF 里中文消失，页面图片和 OCR 都受影响 | macOS 上无头运行的 LibreOffice 看不到系统字体（与沙箱无关，沙箱外结果相同） | `tools/lib/office.py` 每次转换用临时配置目录，并软链接系统中文字体；doctor 改为检查"能转换并渲染中文" |
| PPT 封面这类字少的页被判为低文字页，整份文件降为部分读取 | 把"字少于 20"直接当成"读不出来" | 字少于 20 只触发 OCR；OCR 后仍少于 3 个字才算低文字页；PPT 的文字从文件本身读，只有文件里确实没有文字的幻灯片才做 OCR |
| 快照头写了 url，证据账里的记录没有 | 写入证据账时漏掉了 url | 证据账记录保留 url；测试逐字段核对两者一致 |
| `flags` 在同一行赋值里被提前引用 | Python 元组赋值的求值顺序 | 拆成两行 |
