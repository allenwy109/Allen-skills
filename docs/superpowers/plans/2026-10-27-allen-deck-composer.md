# Allen Deck Composer Execution Design

**Goal:** Turn an accepted semantic blueprint and its three accepted planning records into finished, evidence-led deck pages without changing `report-forge`.

**Interface:** `out_deck.py compose <task>` calls `allen_compose.py`. The composer reads `deck-blueprint.json`, the engine-owned `execution-plan.json`, and `obs/chart-plan.json`, `obs/layout-plan.json`, and `obs/module-fill-plan.json`. Every plan item must be engine-accepted (`done`), name one exact evidence file and hash, bind the current blueprint SHA-256, and carry a reviewer and basis. It writes only `deck-work/pages.html`, `deck-work/page.css`, and `deck-work/.allen/composition-manifest.json`.

**Selection:** The accepted chart plan chooses among `trend-bars`, `comparison-matrix`, `roadmap`, and `evidence-quote`; the accepted layout plan must use an ID in the locked vendor layout catalog; the accepted module-fill plan supplies regions, content, layout, and whitespace decisions. The manifest records each choice and evidence references. A three-page window may not repeat one skeleton.

**Failure behavior:** Missing, incomplete, unaccepted, wrongly bound, or stale plans; unsupported capacity; unsafe content; missing evidence bindings; unknown layout IDs; or a repeated three-page skeleton fail before writing output. Text and attributes are escaped; SVG is renderer-owned. Capacity comes from the actual claim/metric/source collections and is never satisfied by truncation or a caller's lower declaration.

**Engine and placement:** Plan acceptance is established by the locked vendor execution-plan engine (`load`, `effective`, and the `ready` gate), not by locally interpreting a look-alike JSON file. Layout IDs select real 12×6 catalog geometry; ordered layout regions control reading/DOM order, while module layout and whitespace decisions control panel alignment and padding. A browser mutation check must prove that changing one page's accepted plans changes only that page's pixels.

**Safe benchmark output:** The benchmark may replace only a directly nested, marker-owned directory under `out-deck/build/`. Repository roots, the build root, external paths, and existing unmarked directories are rejected before any deletion.

**References constraint:** The locked vendor complete-report contract requires exactly one references page immediately before the back cover. A single-source report therefore keeps its source and locator beside the evidence and turns the required page into a filled provenance audit; it must not emit a nearly empty list.

**Benchmark:** Materialize one locked semantic fixture twice. Each anonymous branch independently performs the real init, accepted planning, ready, compile, assemble, smoke, representatives/production acceptance, and acceptance HTML/PDF QA lifecycle. The reference uses the locked pre-composer fixed-pages author from commit `bfef13d`; the candidate uses `compose`. The reviewer packet contains only neutral labels, common input/blueprint digests, symmetric HTML/PDF/page PNG/contact-sheet hashes, and minimal QA/geometry status. Reviewer HTML receives a stable semantic-token rewrite (`allen-*` implementation names become neutral `review-*` names) and must reproduce every accepted page screenshot byte-for-byte before packaging. Identity mapping, strategies, composition decisions, and reference provenance stay in release-only evidence under `/tmp` and never enter the reviewer packet.

**Success criteria:** deterministic output; at least four forms and four layouts in the composer fixture; sources appear beside evidence; independently parsed rendered claim/metric/source keys exactly equal the blueprint and manifest sets; the complete-report references page is not sparse; formal compile has no preview marker; both benchmark branches pass acceptance HTML/PDF geometry; existing lifecycle and capability tests remain green.
