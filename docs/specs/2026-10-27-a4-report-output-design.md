# A4 正式报告与演示稿双输出设计

日期：2026-10-27  
状态：待用户复核  
适用仓库：Allen-skills

## 1. 背景与问题

Allen-skills 已具备研究、证据账、综合、故事线和正式验收能力，也完整引入了 `report-forge` 的 16:9/4:3 咨询型页面引擎。但当前 `out-report` 仍要求作者为每个任务临时编写 `pages.html` 与 `page.css`。这导致引擎能力与实际成品之间存在明显落差：布局和图表能力没有稳定复用，多 panel 页面可能在临时生成器中丢失，页面容易退化为重复卡片、无效留白和不可读脚注。

更根本的问题是媒介混用。深度研究报告需要 A4 连续阅读、真实分页、跨页表格、页眉页脚和高密度来源；融资路演需要 16:9 画布、单页单结论和演示节奏。两者不能继续共用同一套页面容量与排印规则。

本设计改造整个 Allen-skills 输出层，不针对某一次报告修补，也不依赖 entservice。

## 2. 目标与非目标

### 2.1 目标

1. 正式研究默认输出 A4 自包含 HTML 与同内容 PDF。
2. 按需输出 16:9 咨询型演示稿，并保持 `report-forge` 的成熟能力。
3. 所有场景共用同一份内容真源、证据身份和来源追溯。
4. 用确定性组件与有限布局系统稳定生成专业、克制、数据驱动的咨询报告。
5. 把排版美观作为正式门禁，而不只是检查文件是否成功生成。
6. 杜绝 panel、relation、claim、metric 或关键来源在输出转换中静默丢失。
7. 保持现有研究、证据、方法、综合和验收分层不变，只调整故事线到输出层的交接。

### 2.2 非目标

1. 不重写研究、事实核实、尽调或方法选择流程。
2. 不在第一阶段追求任意页面的无限自由排版。
3. 不把 entservice 的 renderer 作为运行时依赖。
4. 不删除或重写 vendored `report-forge`。
5. 不承诺一次生成即可免除人工成品审查。

## 3. 已确认的产品决策

1. 默认交付是 A4 阅读报告。
2. 16:9 路演稿按需生成。
3. `out-report` 与 `out-deck` 分离，各自采用适合媒介的分页、密度和视觉规则。
4. 两条输出链路共享内容模型和证据账，不维护两份分析结论。
5. 默认视觉方向是国际咨询报告的编辑出版风格：浅色纸面、深灰正文、单一品牌强调色、克制装饰、强调结论和证据。
6. 上游 `consulting-report-forge` 的优秀演示页作为演示稿基准；A4 报告另建立经用户认可的黄金样板。

## 4. 总体架构

```text
证据账 + 07_storyline/slides.json
              │
              ▼
      内容合同转换与完整性检查
              │
              ▼
       07_storyline/report.json
              │
        ┌─────┴─────┐
        ▼           ▼
   out-report     out-deck
   A4 renderer    report-forge
        │           │
        ▼           ▼
  A4 HTML + PDF  16:9 HTML + PDF
```

`report.json` 是媒介无关的正式报告文档模型。它表达章节、内容块、证据关系和呈现意图，不包含像素坐标或具体 CSS。A4 renderer 确定连续阅读和打印排版；`out-deck` 将同一内容真源投影为适合演示的 deck blueprint。

## 5. 内容模型

第一阶段保留 `slides.json` 作为故事线真源，由确定性转换器生成 `report.json`，避免 `core-storyline` 同时维护两份文件。

```text
report
├── metadata
├── executive_summary
├── sections[]
│   └── blocks[]
│       ├── finding
│       ├── prose
│       ├── metric
│       ├── chart
│       ├── comparison
│       ├── table
│       ├── evidence
│       ├── risk
│       └── recommendation
├── references
└── appendix
```

每个 block 至少保留：

- 稳定 ID 和所属章节；
- 支撑的 `claim_refs` 与 `metric_refs`；
- 来源 ID 与定位；
- 事实、估计、预测、假设、判断或建议身份；
- 对应的 panel、角色、关系和展示意图；
- 组件容量所需的结构化数据；
- 与相邻 block 的比较、递进、拆解或总览—细节关系。

转换器必须建立输入到输出的覆盖清单。以下任何一项缺失都使构建失败：正文关键 claim、A 级证据、panel、panel relation、正文引用的 metric、关键来源。不能再允许只取第一个 panel 或用普通文字框代替未处理的内容。

## 6. A4 页面与视觉系统

### 6.1 页面基础

- A4 纵向，PDF 使用真实分页；HTML 使用连续阅读并提供章节导航。
- 统一页边距、内容宽度、栏宽、基线、页眉、页脚和来源安全区。
- 正文默认字号在 10.5–11.5pt 的可读区间，具体值由黄金样板确定。
- 不允许通过缩放整页或低于可读阈值的字体解决容量问题。
- 字体本地嵌入，并明确中文、英文、数字和等宽内容的 fallback。
- 页面在彩色、灰度、屏幕和打印环境下均可区分状态。

### 6.2 首批组件

第一版只实现高频且能覆盖现有场景的 12 类组件：

1. 封面；
2. 目录；
3. 执行摘要；
4. 章节标题；
5. 核心结论与证据；
6. 数据图表；
7. 竞品或方案比较；
8. 客户痛点与需求强度；
9. 市场规模与趋势；
10. 风险、反证与边界；
11. 建议与路线图；
12. 来源和附录。

组件不是装饰模板，而是语义与排版合同。每类组件定义允许的 block、视觉层级、可用布局、容量维度、拆页策略和失败条件。

### 6.3 视觉规则

- 每页有明确的视觉入口、主要结论、主证据和次要说明。
- 主展品的面积和对比度与证明责任匹配。
- 结论、证据、限制和来源不能竞争同一视觉层级。
- 表格强调数字对齐、单位一致、重点行列和跨页表头，减少粗重边框。
- 图表统一色盘、坐标轴、直接标签、预测/估算样式、注释和来源区。
- 色彩用于表达含义，不使用大面积深色卡片、浮夸渐变、玻璃效果或装饰性图标填白。
- 章节页、分析页、比较页、图表页和行动页形成整册节奏；变化服务于叙事，不为凑类型机械换版。
- 留白必须承担分组、强调、阅读停顿或来源安全区功能。

### 6.4 容量与分页

每类组件定义可测试的容量上限，例如表格列数和行数、比较对象数量、图表标签数、正文字符量和来源数量。超过上限时按以下顺序处理：

1. 在保持语义关系的前提下拆成连续页面；
2. 将细节移入附录并在正文建立明确引用；
3. 改用更适合容量的组件；
4. 无法安全处理时构建失败。

禁止缩小字体、压扁行距、截断来源或溢出页面。

## 7. 渲染职责

AI 负责：

- 选择语义组件；
- 决定内容并列、拆解或递进关系；
- 指定主证据和阅读路径；
- 在有限布局集合中说明选型理由。

确定性渲染器负责：

- HTML 结构；
- 字体、间距、网格、颜色和排印；
- 分页与跨页行为；
- SVG 图表和表格表现；
- 页眉、页脚、页码、来源和附录；
- 容量检查与自动拆页。

特殊定制页只作为显式扩展插槽存在，不是默认生产路径，也不能绕过内容绑定与视觉验收。

## 8. 双输出链路

### 8.1 `out-report`

`out-report` 改为 A4 正式报告入口：

1. 检查故事线和证据账；
2. 生成并校验 `report.json`；
3. 选择组件与有限布局；
4. 渲染自包含 HTML；
5. 用浏览器打印生成 A4 PDF；
6. 执行机械、几何、内容与视觉验收；
7. 独立成品审查后登记交付。

不再要求作者为每项任务从零编写完整 `pages.html` 与 `page.css`。

### 8.2 `out-deck`

新增 `out-deck`，承接现有 `report-forge`：

- 输出 16:9 HTML 与 PDF；
- 继续使用上游布局图谱、图表形式、执行清单和审查合同；
- 修正当前临时作者实现可能只读取第一个 panel 的风险；
- 恢复上游展示样板和黄金截图，防止“引擎存在、实际不用”；
- 只有用户明确需要路演、汇报或演示稿时触发。

`out-report` 与 `out-deck` 共享来源、指标、证据身份和内容覆盖检查，但不共享页面 CSS、容量阈值和媒介验收规则。

## 9. 失败与降级

- 内容超出容量：拆页；无法安全拆分则报错。
- 图表缺少结构化数据：退化为证据表或文字分析并记录原因，不虚构数据。
- 字体、浏览器或 PDF 依赖缺失：停止正式 PDF 交付；HTML 只能标记为预览。
- 溢出、遮挡、异常空白、不可读来源或关键内容裁切：验收失败。
- 内容覆盖检查发现丢失：构建失败。
- 独立视觉审查未完成：只能交付预览，不能写成正式完成。
- 旧任务可读取；重新生成时明确声明采用新版 A4 输出。若仍需要旧版 deck，改走 `out-deck`。

## 10. 质量门禁

正式报告必须依次通过：

1. **内容完整性**：关键 claim、A 级证据、panel、relation、metric 和来源均被覆盖。
2. **证据一致性**：数字和身份来自证据账，未核实内容不得伪装成事实。
3. **机械排版**：无溢出、遮挡、孤行、断裂表格、异常空白页或不可读来源。
4. **组件容量**：全部组件处于允许范围，超限已经拆页或构建失败。
5. **整册视觉**：层级、平衡、对齐、密度、节奏、图表表达和专业感达到基准。
6. **黄金样板**：关键组件的截图与批准基准没有未解释的明显退化。
7. **最终媒介**：HTML 与 PDF 均实际打开检查，内容与页序一致。
8. **独立审查**：没有未解决的 Blocking 或 Major 问题。

自动流程应从最终 PDF 选出最密页、最大空白页、最复杂图表页、来源最多页和最强结论页，要求审查者查看实际截图。自动检查只能定位问题，不能替代对美感与可理解性的判断。

## 11. 测试策略

### 11.1 契约测试

- `slides.json → report.json` 的字段映射；
- 多 panel、多 relation 和 anchor panel 完整保留；
- claim、metric、来源和身份覆盖；
- 丢失或未支持内容时失败；
- 同一输入产生稳定输出。

### 11.2 组件测试

- 12 类组件的最小、正常、临界和超限样本；
- 中文、英文、数字、长 URL 和长来源；
- 自动拆页、附录迁移和失败行为；
- 表格跨页表头、图表标签和直接注释。

### 11.3 PDF 几何测试

- A4 页面尺寸和页边界；
- 页眉页脚和页码；
- 溢出、裁切、重叠、孤行和空白页；
- 图表、表格和来源安全区；
- HTML 与 PDF 内容清单一致。

### 11.4 黄金截图测试

先制作并由用户确认封面、执行摘要、市场分析、竞品矩阵、趋势预测、风险页、建议路线图和来源页等黄金样板。固定数据生成 PNG，使用像素或感知差异检测退化；超过阈值必须人工确认，不能自动更新基准。

### 11.5 场景验收

首批样本覆盖创业点子评估、企业全景分析、BP 评审、行业研究、定量图表密集报告和文字证据密集报告。不能只用当前 AIDC 案例证明系统有效。

## 12. 完成标准

本改造只有同时满足以下条件才算完成：

1. 所有正式研究入口默认生成 A4 HTML/PDF。
2. A4 HTML 与 PDF 可连续阅读，内容、来源和页序一致。
3. 关键内容没有从故事线到成品的静默丢失。
4. 代表组件达到用户确认后的黄金样板。
5. 六类场景样本均通过契约、组件、几何和视觉验收。
6. `out-deck` 保留 16:9 咨询演示能力，并达到上游示范的视觉基准。
7. 两条输出链路均没有未解决的 Blocking 或 Major 成品问题。
8. 仓库安装、自检、文档与统一验收均反映新的输出架构。

## 13. 实施边界与顺序

该设计适合一个实施计划，但应分阶段交付：

1. 建立 `report.json` 合同、转换器和内容覆盖检查；
2. 建立 A4 design tokens、页面骨架和首批组件；
3. 接通 HTML/PDF、容量、分页和几何检查；
4. 改造 `out-report` 并迁移验收；
5. 新增 `out-deck`，把现有 report-forge 链路迁入；
6. 建立黄金样板、视觉回归和多场景验收；
7. 更新安装、架构、场景路由和用户文档。

每一阶段都应先写失败测试，再做最小实现；不得在同一阶段顺带重构研究或证据系统。
