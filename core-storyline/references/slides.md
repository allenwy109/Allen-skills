# 拆页

## 1. 演讲型还是阅读型

| | 演讲型 | 阅读型 |
|---|---|---|
| 密度 | 低：3–5 条或 1 张图，细节进讲者备注 | 高：页面自己能读懂 |
| 页数 | 按时长硬约束 | 按逻辑完整度，通常比演讲型多 30–60% |
| 备用页 | 至少 3 页（检查脚本报错） | 可选（检查脚本只提示） |

两种都用行动标题。

## 2. 页数

- 正式汇报每页 1.5–2 分钟，含讨论 2–3 分钟。
- 上限只约束主 deck（封面、目录、内容、过渡、附录），备用页单列。故事板写主 deck 页数、备用页数和合计。
- 页数上限只来自用户的要求，默认不设；写在 slides.json 的 `deck.page_limit`。
- 超页按顺序处置：合并同级的次要页 → 移入备用页 → 进附录。禁止删内容、压条目、缩字号。
- 过渡页超过 4 页，说明章节太碎。

## 3. 稿件到页面的映射

中心论点 → 执行摘要页（紧跟封面）；SCQA → 开场 1–3 页；支撑点 → 章（可设过渡页）；子论点 → 内容页；证据 → 页面主体；细节 → 讲者备注或备用页；附录 → 附录页。

## 4. 故事板（05_storyboard.md）

Deck 设定（类型、时长、上限、主 deck 页数、备用页数、合计、语言、结尾类型）和超页处置记录；故事板表（页码、章节、页面类型、行动标题、核心证据卡片、对应稿件段落）；横向检查（只读标题列，一屏读完是否完整、没有跳跃）；纵向检查表（页码、标题、正文是否支撑、不支撑的内容移到哪）；备用页清单；映射核对。

## 5. 逐页内容（06_slides.md）

页块格式：

```
## P02 ｜ 01 收入 ｜ 数据图表
**行动标题**：收入两年增长 77.8%，规模仍小
**正文**：
- 收入从 1800 万元增至 3200 万元〔card-0001｜M001 p12〕
**可视化建议**：两年柱形，零基线，单位万元
**讲者备注**：……〔card-0001〕
**来源**：card-0001｜M001 p12
**追溯**：第一章；card-0001
```

- 页面类型（17 种）：封面、目录、执行摘要、章节过渡、观点+证据、数据图表、对比、流程、时间线、矩阵、案例、建议、下一步、风险、备用、附录、结尾。
- 正文和讲者备注里要直接写卡片引用：卡片只有出现在正文、可视化建议、讲者备注里才算安置，"来源"字段不算。
- 备用页另写 `**触发**：`（什么情况下翻到）和 `**拉回**：`（答完怎么回到主线）。
- 一页一个核心信息；撑不住标题的内容移到备注或备用页；不新增库外事实。

**行动标题四步**：写话题 → 问这页到底要说明什么 → 把抽象词换成数字 → 检查是否需要正文支撑（不需要说明这页可以删）。建议 ≤30 字、最多两行；太长通常是两个结论，考虑拆页。封面主标题可以是话题式。

**各类页面的标题**：目录写"本报告回答 N 个问题"；执行摘要写中心论点；过渡页写本章结论；对比页写对比得出的判断；流程页写产出或卡点；时间线写转折或节奏；矩阵写落点和含义；案例按背景 → 做法 → 结果 → 启示；下一步写明确的请求；备用页写被问的问题；主 deck 的最后一页（封底之前）只能是建议或下一步。

**图表建议**：先定比较关系，再选图——

| 关系 | 选 | 不选 |
|---|---|---|
| 成分 | 饼图（≤5 项）、堆叠条、瀑布；占比随时间变用面积图 | — |
| 项目排序 | 横条 | 饼图 |
| 时间序列 | 折线看变化率，柱形看绝对量 | — |
| 频率分布 | 直方图、箱线图 | 折线 |
| 相关性 | 散点、气泡；标题不写因果 | — |

每个图表页写清：图型及理由；所需数据和数值（来自卡片）；高亮重点；轴、单位、口径、时间范围；图题写成结论句。非数据页给版式或图示建议。需要选图时可以用 thinkcell 的 `tc_advise` 取得推荐（首选加 2 个备选），结合受众判断是否采纳，不采纳写理由。

**讲者备注**：可以直接念的话，不是提纲；开头承接上一页，结尾用内容过渡到下一页；写页面上没有的细节（来源、限定、被追问时的补充）；口语化；中文每分钟 200–250 字。

**备用页**：3–5 页，首选没进主线的 A/B 卡；一页一个问题，标题是问题或答案；照常标来源和追溯。常见追问：怎么算的、口径是什么、最坏情况、为什么不选别的方案、同行怎么做。

## 6. 整册图表与版式规划

拆页时就要按报告引擎的"整册图表与版式规划"（`<运行时>/vendor/report-forge/references/content-authoring.md`）统筹全册：

- 通览每页要证明的关系，**主动找没用过、又适配的图型和版式**，相同图型可以配不同版式，同一版式也可以装不同图型；
- 保留重复要写具体理由（如同一组地区用共同量尺逐页比较），"保持统一""组件现成"不算理由；
- 不为凑种类造数据、堆图或改颜色。

## 7. slides.json

`storyline sync` 从 06_slides.md 同步文字字段（页面类型、行动标题、章节、正文、讲者备注、来源、追溯），并把讲者备注和备用页写进 sidecar.json。下面这些判断类字段由作者直接写在 slides.json 里（schema：`<运行时>/tools/lib/schema/slides.schema.json`），sync 不会动：

| 层级 | 字段 | 写法 |
|---|---|---|
| deck | `story_mode`、`arc`（other 时加 `arc_reason`） | 与 03_storyline.md 的故事线模式一致 |
| deck | `brief` | 研究问题、目的、范围、期间、基准、约束、成功标准（取自简报和故事线） |
| deck | `answer_claim_refs` | 中心论点对应的主张，必须由某个正文页承担 |
| deck | `cover`、`page_limit`、`kind` | 封面信息（date 必填）、页数上限、演讲型或阅读型 |
| 每页 | `page_role`、`story_beat` | 页面角色（封面、章节、分析、决策、行动、风险、附录、封底）和故事节拍 |
| 正文页 | `proves` | 这页的画面能证明的关系 |
| 正文页 | `adds` | 读者读完这页比上一页多知道什么（至少 12 字，相邻页不能近似重复） |
| 正文页 | `subtitle` | 口径：单位、期间、范围；不复述标题、不写数字 |
| 正文页 | `claim_refs`、`metric_refs` | 本页承担的主张和需要单独显示的指标 |
| 正文页 | `density` | profile（密、均衡、疏）、evidence_units（每个证据单元的角色和用途，用途至少 8 字）、space_intent |
| 正文页 | `panels` | 每件展品：id、用途、承担的主张、形式（如 svg.custom、html.table、kit.dumbbell）、关系、选型理由、备选与取舍、区域（slot、role、span）；恰好一个 role=primary |
| 正文页 | `relations` | 多件展品时，说明它们为何必须一起看（对照、拆解、递进、互补、总览与细节、边界） |
| 正文页 | `visual_intent` | layout（custom 或目录布局）、reading_path、layout_reason、repetition_reason |

自定义布局的 slot 只能是 main、left、right、top、bottom、aside、full。可用形式和每种形式允许的关系，在引擎目录里查：`node -e 'const f=require("./assets/deck-forms.js"),c=require("./scripts/form_contract.cjs"),e=f.get(process.argv[1]);console.log(c.OVERRIDES[e.form]||c.RELATIONSHIPS[e.family]||[])' html.table`（在 `<运行时>/vendor/report-forge` 下运行）。
