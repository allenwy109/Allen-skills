# 内容稿

## 1. 骨架

标题 → 执行摘要 → 引言（SCQA，只铺垫不论证）→ 每个支撑点一章（章首句即结论，下设子论点配证据）→ 结论与建议 → 风险、前提与待决问题 → 方法与局限 → 故事线模式要求的必备章节（见 storyline-method.md 第 7 节）→ 附录（A 详细数据、B 案例、C 方法与计算、D 术语口径、E 来源清单）。

- 章序等于结构树的顺序。
- 某章撑不起来，回阶段 3 改主线，不注水。

## 2. 段落

- 一段一意；首句即观点句（能直接改写成页标题）。
- 能用数字、案例、原话，就不用形容词。
- 主语明确；被动句只在施动者无关时用。
- 不用"首先、其次、最后"，用因果、递进、对照来连接。
- 段长 3–6 句。原话加引号，注明说话人的角色和来源。
- 推荐反向写作：先写全部首句，排成一列检查论证链，再扩写。

## 3. 标注

| 标注 | 写法 | 清洁版 |
|---|---|---|
| 卡片引用 | `〔card-0012｜M003 p12〕`；多张卡用"、"；竖线全角半角都可以 | 删除 |
| 推断 | `（推断｜依据 card-0018、card-0031）`，紧挨所修饰的数字或判断 | 保留 |
| 缺口 | `【待补充：需要什么证据】` | 保留 |
| 外部补充 | `【外部补充：……（来源：……）】` | 保留 |

纪律：

- 卡片 ID 必须存在。
- 推断、建议、目标、测算类数字必须紧挨数字带标记并写依据；判断词离数字远了不算。
- 缺口不填充。
- 日期和序号不单独引注；但出现在带引用的句子里时，要能在所引卡片里找到——不要为了让检查安静而改写成"上次会议"。
- 自己算的数走派生卡。

## 4. 执行摘要

200–400 字，可以独立阅读：中心论点 1 句 → 2–4 条理由，各带关键数字 → 结论或请求 1 句。

- 不写导航句（"本报告分为三部分"）；
- 不出现正文没有的数字；
- 不出现【待补充】（可以写"证据见第 X 章"）；
- 自测：发给不了解项目的人，他能说出要他做什么。

## 5. 结论与建议；风险、前提与待决

- 建议的动作要可执行；写优先级和排序依据；负责人和时间只在材料支持时写，否则【待补充：责任人】；每条指向正文某章；不引入新证据。
- 风险、前提、待决分开写：风险写触发条件、影响、缓解；前提被推翻时结论要重估；待决写谁能回答、需要什么信息。少数派证据在这里露脸。
- 附录的来源清单只列实际引用过的来源。

## 6. 删词

检验法：划掉形容词和副词后，话仍然成立。检查脚本会提示这些词：

- 套话：赋能、抓手、闭环、打通、拉通、颗粒度、沉淀、组合拳、全方位、多维度、深度融合、持续发力、助力、痛点；
- 没有数字支撑的程度词：显著、大幅、有所、进一步、极大；
- 没有主语的判断：业内普遍认为、据了解、众所周知。

## 7. 母版与清洁版

- 母版带追溯标注；清洁版由 `storyline clean` 机械生成：只删卡片引用，推断标注和【待补充】【外部补充】保留。
- 不手改清洁版；检查脚本会重新生成并比对，不一致就报错。
- 用户要求连推断和缺口也去掉时，另存对外版，并在审计里登记移除了什么。
