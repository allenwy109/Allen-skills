# 故事线方法

## 1. 金字塔四原则

| 原则 | 怎么判断做到了 |
|---|---|
| 结论先行 | 首段、每章首句、每页标题读到的都是结论 |
| 以上统下 | 读完下层，得到的信息不超过上层那一句 |
| 归类分组 | 同一组属于同一个逻辑类别，能用一个词概括 |
| 逻辑递进 | 打乱顺序后明显变差，才说明排序有依据 |

- **纵向检查**：每层断言下面写出读者此刻会问的那句话，下一层必须正好回答它。答成另一个问题就是断链。
- **横向检查**：同层两两不重叠、没有遗漏的第三类（MECE）；一次只用一个分组维度（时间、组织、价值链、重要性、因果）；排序依据四选一（时间、结构、重要性、因果）并写进故事线。
- **演绎还是归纳**：演绎在前提成立时结论必然成立，但前提被攻破整条链就崩，适合反直觉的结论或专业受众；归纳是概率性的、一个反例就能打穿，适合时间紧、要好记的场合。常见做法是主体归纳、关键结论演绎；同一组里不混用。

## 2. SCQA

SCQA 是开场和定义问题的框架，成品里不要写成"一、情境 二、冲突"这样的小标题。

- S：念出来受众不会反对，而且简短。
- C：具体、有证据、有数字和时点，让人"咦"一声。C 的强度决定整份报告的上限。
- Q：由 C 自然引出，只有一个，用受众的语言。
- A：可以执行的断言，有方向、有边界，正面回答 Q。

**开场顺序**（只影响开场）：

| 顺序 | 适合 | 风险 |
|---|---|---|
| S-C-A 标准式 | 受众缺背景；书面报告 | 高层嫌啰嗦 |
| A-S-C 开门见山 | 高层时间紧、结论已被期待 | 缺背景时答案悬空，要在备注里补 |
| C-S-A 突出忧虑 | 制造紧迫感、推动行动、争取资源 | 用多了显得危言耸听 |
| Q-S-C-A 突出信心 | 受众带着明确问题来，如答标评审 | 问题问偏，整个框架失效 |

怎么选：受众带问题来 → Q-S-C-A；已经认同结论 → 用 C 开路；不需要背景且时间紧 → A-S-C；其余用标准式。

**SCQA 的 10 种失败**：C 没有数字、时点或主语；没有 Q；Q 不止一个；A 只是个话题；A 答了别的问题；S 太长；A 没有真正被论证；为了顺删掉不利的 C；纵向断链；横向不 MECE。

## 3. 生成候选主线

- **自下而上**：按内容亲缘（不按来源）把卡片归组，每组连问三次：组名是什么 → 所以呢（组级观点）→ 它支持什么上层结论。答案是"情况很复杂"，说明没归好，重新切。
- **自上而下**：受众现在信什么？要信什么才会做决定？此刻最担心什么（通常就是 Q）？
- 两头交汇。对不上，说明 Q 问偏了，或者卡片里还有没归出来的东西。

**真正有差异的候选**有三个旋钮：角度（换因果起点）、结论强度（保守、中性、激进）、受众侧重。只换措辞、只调顺序、明显陪衬的都不算。材料只支持一条线时，只写一条并说明原因。

每个候选写：一句话中心论点（电梯测试）；SCQA 各 1–3 句；推荐开场顺序及理由；3–5 个支撑点（归纳还是演绎、排序依据、MECE 自检、挂载的 A/B 卡、证据强度、缺口）；放不进主线的信息和安置方式——写不出来，说明主线太窄。

## 4. 假设—证据—结论链

每个支撑点一条：

- 证据栏只放卡片 ID；
- 推断栏显式标注，并写依据卡；
- 结论栏的句子就是下一页标题的素材；
- 证据不足写缺口和补法；
- 强度三档：强（多个独立来源或权威一手）、中（单一可靠来源）、弱（推断、个例、来源存疑）。弱证据不能单独支撑中心论点。

## 5. 压力测试

对推荐主线做三类质疑，答案只能落进稿件或缺口清单，不允许只写"已考虑"：

| 类型 | 问法 | 答不上怎么办 |
|---|---|---|
| 证据 | 这个结论的证据够吗？ | 补证据，或降为【待补充】 |
| 反例 | 有没有相反的情况？ | 写进风险或待决问题 |
| 代价 | 最坏情况是什么？止损线在哪？ | 补下行分析和止损条件 |

## 6. 结构树与安置计划

中心论点 → 支撑点 → 子论点 ← 卡片 ID（强度），缺口写在节点上。树下列"移出主线的重要信息 → 去向"和待定池，注明这只是计划（实际安置以内容稿和逐页为准）。

## 7. 故事线模式

按受众听完要做什么动作来选。`03_storyline.md` 里写一行"故事线模式：<名称>"，slides.json 的 `deck.story_mode` 和 `deck.arc` 要与之一致（检查脚本会核对）：

| 模式 | Q | A 的样子 | 骨架 | 常见翻车 | arc | 必备章节 |
|---|---|---|---|---|---|---|
| 问题诊断→方案 | 为什么、怎么办 | 根因是 X，所以改 Y | 现象 → 分层根因 → 方案 → 实施与代价 | 不挖根因；方案对不上根因 | problem-to-fix | — |
| 方案比选 | 选哪个 | 选 B，附淘汰理由 | 评估维度 → 对照 → 推荐 → 风险与回退 | 维度事后凑；不讲推荐方案的代价 | opportunity-to-choice | 维持现状方案 |
| 请求批准 | 给不给 | 请批 X（金额、人数、授权） | 缺口 → 为何现在 → 投入产出 → 风险及不批的后果 | 没有明确的请求 | opportunity-to-choice | 不批的后果 |
| 进展汇报 | 现在怎样 | 整体在轨，某项偏离需要决策 | 目标 → 关键结果 → 偏差与原因 → 下一步与请求 | 流水账；偏差轻描淡写；没有请求 | other | 请求 |
| 机会论证 | 要不要做 | 要，以某种方式、某个节奏 | 机会 → 胜算 → 打法与资源 → 风险与止损线 | 只讲好处；把市场大当成能赢 | opportunity-to-choice | 止损线 |
| 复盘 | 当初为何如此 | 可复用的判断 + 要改的机制 | 结果对目标 → 归因（可控、不可控）→ 复用与修改 | 归因全在外部；教训不可执行 | other | 要改的机制 |
| 行业研究 | 行业往哪走 | 趋势确立、格局演化的方向 | 格局 → 驱动 → 价值链 → 关键变量 → 启示 | 资料汇编没观点；有观点没证据链 | evidence-to-view | 分歧与不确定性；未解问题 |
| 公司研究 | 这家公司怎样 | 有边界的观点，不做投资判断 | 身份与沿革 → 团队 → 产品与客户 → 营收与盈利 → 竞争 → 风险与未知 | 把公司宣传当事实 | evidence-to-view | 风险与未知；补齐路径 |
| 尽调结论 | 投不投 | 投、不投、有条件投 | 业务 → 财务 → 团队 → 风险 → 估值与条件 | 风险章写成免责声明 | uncertainty-to-bet | 风险与红旗；补齐路径 |

- 所有类型都要有"方法与局限"一节。
- arc 为 other 时，slides.json 写 `arc_reason`（推理顺序是什么，为什么四条默认弧线都不适用）。
- 行业研究的变体按支撑点排序区分：技术深潜按"机制 → 证据 → 边界"，文献综述按"共识 → 争议 → 空白"，政策法规按"条文 → 生效 → 影响 → 待确认"（另加"需向专业人士确认的问题"），事实核查按"评级 → 证据链 → 口径"（另加"什么证据会改变评级"）。
