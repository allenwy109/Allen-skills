# 管理咨询方法库

这里只管“有哪些方法、各自什么时候能用、怎么用对”。完整的解题流程（拆问题、选方法关口、核实、审查、综合）在能力层：

- 拆问题：`../core-framing/`
- 选方法：`../core-method-select/`（本表是它的查表依据）
- 核实：`../core-evidence/`
- 综合与输出格式：`../core-synthesis/`

用户只问一个方法时（“用 SWOT 分析一下”），也要先过 core-method-select 的前提检查：前提不满足就说明，并给出换用的方法。

## 和另外两个方法库的分工

- 本库回答“**企业该往哪走、为什么经营成这样**”：从外部视角诊断方向和业绩。
- `lib-management` 回答“定好的事怎么做成、团队怎么带好”。
- `lib-personal` 回答“我自己怎么更高效”。
- 例：“战略定了落不了地”——先用本库的 7S 诊断卡在哪里，再用 lib-management 设计目标分解和变革推进。

## 选法表

四列的意思：**情况**按问题性质找，不按措辞找；**前提**缺了就不能用这个方法（先补信息，或按“换用”降级）；**换用**写成“如果……→ 改用……”。

**A. 还不知道问题在哪**
| 情况 | 首选 | 前提 | 换用 |
|---|---|---|---|
| 对情况了解很少 | 议题树 | 主导问题已经说清楚 | 问题还说不清 → 先用 5W2H 或“标准 − 现状”；已有明确猜想 → 假设树 |
| 已有方向性判断，时间紧 | 假设树 | 有一个能被数据证伪的假设，且拿得到验证数据 | 假设被数据推翻 → 重建树；拿不到验证数据 → 议题树 |
| 指标可以用公式拆 | 公式法议题树（利润 = 收入 − 成本） | 有分项数据，至少能估到数量级 | 完全没有数据 → 定性议题树，并列出要补的数据 |
| 多个方案要做决定 | 是否树（决策树） | 问题结构已经清楚，选项明确 | 选项还没想全 → 先用议题树或头脑风暴 |

**B. 业绩问题**
| 情况 | 首选 | 前提 | 换用 |
|---|---|---|---|
| 利润、收入、毛利下滑 | 利润树（收入 = 量 × 价，成本 = 固定 + 可变） | 至少两期的分项收入和成本 | 定位到收入侧 → 接 3C；定位到成本侧 → 接价值链或标杆分析；没有数据 → 定性议题树 |
| 和同行比差在哪 | 标杆分析 / 竞争态势矩阵（CPM） | 有可比的对标数据（同口径、同期间） | 拿不到对标数据 → 定性的 KSF 对比 |
| 财务上哪块出了问题 | 杜邦分析 / 财务雷达图 | 有完整的三张报表 | 只能看出结果，要找原因 → 接利润树 |
| 成本太高怎么降 | 价值链 + 零基预算 | 能按环节拆出成本 | 成本来自质量或流程浪费 → lib-management 的精益；正处于投入换增长的阶段 → 先别一味降本 |

**C. 行业与市场**
| 情况 | 首选 | 前提 | 换用 |
|---|---|---|---|
| 行业值不值得做 | 波特五力 | 行业边界清楚、结构相对稳定 | 技术剧变、边界模糊 → 补 PEST 和情景规划；想看冲击怎样传导 → SCP |
| 外部环境变化有什么影响 | PEST / PESTEL | 能拿到较新的政策、经济、技术信息（注意时效） | 要落到企业自身 → 必须接 SWOT |
| 市场有多大 | 市场规模估算（TAM/SAM/SOM，自上而下 + 自下而上） | 两种算法的关键输入都能找到来源 | 已有可靠的行业统计 → 直接引用并注明来源；两种算法差距超过一倍 → 找出哪个假设错了，不取平均 |
| 这个行业靠什么赢 | 关键成功因素（KSF） | 能找到成功者和失败者做对比 | 只想看行业吸引力 → 五力；要量化比较竞争者 → CPM |
| 未来不确定性很大 | 情景规划 | 已识别出 2 个关键不确定因素 | 不确定性不大或决策短期可逆 → 常规预测即可 |

**D. 战略方向与增长**
| 情况 | 首选 | 前提 | 换用 |
|---|---|---|---|
| 明年战略重点放哪 | SWOT → TOWS 组合 | 内部优劣势有事实依据，外部机会威胁有较新的信息 | 只列清单不排序 → 接 TOWS 或 IFE/EFE 加权打分；只看行业 → 五力；只看宏观 → PEST |
| 靠什么增长 | 安索夫矩阵 | 现有业务没有在大量流失客户 | 现有业务在流失 → 先用利润树或 3C 诊断；要平衡长短期 → 增长三层面 |
| 要不要进入这个市场 | 市场进入框架：吸引力 → 胜算 → 进入方式 → 财务测算 | 目标市场的范围已经定义清楚 | 只是在现有市场增长 → 安索夫或利润树；进入方式确定是收购 → 并购框架 |
| 多条业务该投哪个、砍哪个 | BCG 矩阵 | 有各业务的市场增长率和相对份额数据；业务之间协同弱 | 因素更复杂 → GE 矩阵；拿不到份额数据 → 定性 KSF 对比；只有一条业务 → 利润树或竞争战略；协同强 → 不能单独评估 |
| 用什么方式竞争 | 波特通用战略（成本领先、差异化、聚焦） | 行业本身值得做 | 行业不值得做 → 先用五力；高度同质化只能拼价格 → 蓝海战略 |
| 市场太挤，怎么突围 | 蓝海战略 | 对行业竞争要素和客户需求了解透彻 | 行业还在快速增长、现有打法有效 → 不必重构 |
| 商业模式要不要改 | 商业模式画布 | 只用来描述现状和备选 | 要评估好坏 → 结合五力、利润树或市场规模 |
| 要不要收购这家公司 | 并购框架：战略契合 → 标的质量 → 协同 → 估值 → 整合风险 | 已经想清楚为什么要扩张；能拿到标的的基本财务信息 | 还没想清楚为什么扩张 → 先用增长路径；纯合作不必控股 → 战略联盟 |

**E. 客户与营销**
| 情况 | 首选 | 前提 | 换用 |
|---|---|---|---|
| 份额为什么被对手抢走 | 3C（公司、客户、竞争对手） | 能拿到客户和竞争对手的信息 | 纯成本或运营效率问题 → 利润树、价值链或精益 |
| 该服务哪些客户 | 客户细分 → STP | 客户需求有差异；细分维度能测量、能触达、有利润差异 | 大宗商品、需求高度一致 → 细分意义不大 |
| 营销策略哪里有问题 | 4P（服务业 7P） | 已经清楚卖给谁 | 还没想清楚卖给谁 → 先做 STP；行业整体萎缩 → 先看 PEST 或五力 |
| 该怎么定价 | 定价三角：成本、竞品、客户价值 | 知道成本结构和主要竞品价格 | 问题其实是产品不被需要 → 先用客户细分或 3C |
| 客户为什么不满意、为什么流失 | 客户旅程分析 | 能接触客户：访谈、调研或行为数据 | 完全接触不到客户 → 用投诉和丢单记录列卡点清单，并标明局限 |

**F. 组织诊断**（只诊断卡在哪，推进变革交给 lib-management）
| 情况 | 首选 | 前提 | 换用 |
|---|---|---|---|
| 战略定了为什么落不了地 | 麦肯锡 7S | 能访谈到多个层级的人 | 问题来自外部市场 → 五力或 3C；要快速参与式诊断 → 韦斯伯德六盒模型；只是个别团队的问题 → lib-management |
| 要做大的组织变革，先改哪里 | Burke-Litwin 模型 | 需要看清因果和变革先后，且有足够的组织信息 | 只想快速排查 → 7S |
| 有哪些人会支持或反对 | 利益相关者分析（影响力 × 态度） | 方案涉及多方 | 只涉及个人或小团队 → 不必 |

**G. 呈现结论**：一律用 SCQA 开头、金字塔原理展开，格式见 `../core-synthesis/`。讲个人经历用 STAR（lib-personal）；向领导推销方案用 SCRTV。

找不到合适的现成框架时，自下而上建结构：把想法全列出来，相近的分组，给每组起标题，再检查组间是否 MECE。不要为了用框架而削足适履。

## 卡片在哪

选定方法后先读卡片再动手。方法清单和卡片路径见 `references/method-index.md`，卡片在 `references/methods/`。每张卡片都有“前提与不能推出什么”和“常见误用”两节，要逐条对照。

## 输出形态

企业方向的问题默认用汇报格式（SCQA + 正文 + 附录），见 `../core-synthesis/`。
