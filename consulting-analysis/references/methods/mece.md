# 方法卡片：MECE 与建结构

## 它解决什么问题
把信息或问题分组时做到“相互独立、完全穷尽”：既不重复，也不遗漏。这是议题树、金字塔原理和几乎所有框架的基础。

## 什么时候用
- 拆解问题、组织论点、设计调研清单、写报告目录时。
- 找不到现成框架，需要自己建结构时。

## 什么时候不用
- 早期头脑风暴阶段：先求多，再用 MECE 整理。过早追求 MECE 会扼杀新想法。

## 五种分法，怎么选
| 分法 | 例子 | 什么时候用 |
|---|---|---|
| 公式法 | 销售额 = 单价 × 数量 | 能用公式拆的，优先用，最不容易漏 |
| 过程法 | 研发 → 生产 → 销售 → 服务 | 汇报项目进度，分析流程问题 |
| 要素法 | 组织架构、4P | 描述一个事物由哪些部分组成 |
| 二分法 | 国内 / 国外，新客 / 老客 | 快速切一刀，但要确保两边合起来是全部 |
| 矩阵法 | 重要 × 紧急 | 两个维度交叉，分出四类 |

## 自下而上建结构（没有现成框架时）
1. 把所有相关想法写在一张纸上，不加评判。
2. 把相近的想法连线、分组。
3. 给每组起一个概括性的标题。
4. 检查组与组之间是否重叠、是否遗漏。
5. 调整后排序（时间、结构或重要性顺序）。

## 输出模板
```
上层问题/观点：……
├─ 分组 1（分法：……）
├─ 分组 2
└─ 分组 3
MECE 检查：是否有重叠？……  是否有遗漏？……
```

## 常见误用
- 把“其他”放在最高层级。实在有归不进去的内容，只能放在较低层级。
- 同一层混用不同维度（一个按地区、一个按产品）。
- 为了凑齐 MECE 而牺牲洞察：分得很整齐，却没有抓住真正的关键。
- 分得太细，每层超过 5～7 项，读者记不住。
