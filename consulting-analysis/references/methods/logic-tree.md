# 方法卡片：逻辑树（议题树 / 假设树 / 是否树）

## 它解决什么问题
把一个大而模糊的问题拆成可以分头处理、能分出轻重缓急的小问题，保证不重不漏，并让团队对解题框架达成共识。

## 三选一：用哪种树
| 你的处境 | 用哪种 | 原因 |
|---|---|---|
| 对情况了解很少，还说不出“可能是什么原因” | 议题树 | 先求完整，避免过早锁定错误方向 |
| 已经有一个方向性判断，时间又紧 | 假设树 | 直接对准要验证什么，分析更聚焦、更快 |
| 要在几个行动方案之间做决定，或向领导呈现选项 | 是否树 | 把决策逻辑按顺序展开，便于拍板 |

实际项目里常常是先用议题树，了解足够后改成假设树，最后用是否树呈现决策。

## 不适用的情况
- 问题本身还没定义清楚：先用 5W2H 或“标准 − 现状”把问题说清楚，再建树。
- 已发生的运营或质量问题，因果链清楚：直接用 5WHY 或鱼骨图更省事（见 management-toolkit 的根因分析卡片）。

## 操作步骤
1. 在树根写下主导问题（具体、可行动的一句话）。
2. 选拆分方式：能用公式就用公式（如“利润 = 收入 − 成本”）；否则按流程、要素或矩阵拆。
3. 每一层检查 MECE：同一层的分支不重叠、合起来能完整回答上一层。
4. 拆到能直接用数据回答、或能直接指派给某个人去做的程度就停。
5. 用 80/20 剪枝：标出最可能影响结论的 2～3 个分支，其余写明“暂不展开”。
6. （假设树）每个末端写清：要验证的假设、需要什么分析、数据从哪里来。

## 输出模板
```
主导问题：……
├─ 分支 1：……（假设：……｜需要的数据：……）
│   ├─ 1.1 ……
│   └─ 1.2 ……
├─ 分支 2：……
└─ 分支 3：……
重点深挖：分支 X、Y（理由：……）
暂不展开：分支 Z（理由：……）
```

## 常见误用
- 把“其他”放在第一层。
- 同一层混用不同的拆分维度（比如一个分支按地区，一个按产品）。
- 假设被数据推翻后还不改树。
- 拆得太细，每个分支都做，失去重点。

## 示例（来自资料中的公共图书馆案例，已简化）
主导问题：图书馆如何在不超出预算的前提下，于 6 个月内改善读者服务？
- 为什么业绩变差？（藏书、员工、布局、借阅流程哪一项变了）
- 延长开放时间有没有明显改善空间？
- 更好地选书能否改善？
- 让借阅现有资料更方便能否改善？

分析后发现，主要原因是新馆布局变化，读者找不到常用书。结论：把常用书移到前面、做一次新馆布局宣传，并把新书预算临时转去做标识。

资料：《麦肯锡方法论：发现和分析问题的七个步骤》《麦肯锡咨询工具与方法模型》。
