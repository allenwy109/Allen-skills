# 方法卡片：客户旅程分析与 NPS

## 它解决什么问题
站在客户的角度，看他从知道产品到购买、使用、续购的全过程，找出体验最差、最容易流失的环节。

## 什么时候用
- 客户满意度低、流失率高、复购率低。
- 想找出“企业以为提供的”和“客户实际体验到的”之间的差距。

## 什么时候不用
- 没有办法接触客户（访谈、调研、行为数据都拿不到），分析会变成内部臆测。

## 操作步骤
1. **选一类客户和一个场景**：比如“中小企业客户首次购买并上线”。
2. **画出旅程阶段**：认知 → 考虑 → 购买 → 上手 → 使用 → 求助 → 续约或推荐。
3. **每个阶段记录**：客户想做什么、接触了哪些渠道、感受如何（满意或受挫）。数据来自访谈、调研和行为数据。
4. **找出关键时刻**：对整体感受影响最大的节点，往往是体验最好或最差的时刻，以及结尾。
5. **衡量忠诚度**：用 NPS（“你有多大可能向朋友推荐我们”，0 到 10 分）区分推荐者、被动者和贬损者，并追问原因。
6. **排定改进优先级**：先解决造成最多流失的环节。

## 输出模板
```
| 阶段 | 客户想做什么 | 接触点 | 感受 | 痛点 | 改进机会 |
|---|---|---|---|---|---|
关键时刻：……
NPS：……（贬损者的主要原因：……）
优先改进：……
```

## 常见误用
- 用内部流程代替客户旅程，画的是公司怎么做，而不是客户怎么经历。
- 只收集分数，不追问原因。
- 改进措施分散在各部门，没有人对整个旅程负责。
