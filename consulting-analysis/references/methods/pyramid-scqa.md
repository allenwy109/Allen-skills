# 方法卡片：金字塔原理与 SCQA（结论表达）

## 它解决什么问题
把分析结果组织成一份让人快速听懂、愿意接受的汇报：先说结论，再给理由，理由有条理、有依据。

## 什么时候用
- 所有需要给别人看的分析结论、方案、报告、邮件。
- 临场发言、向领导汇报、说服别人。

## 什么时候不用，或换用什么
| 情况 | 换用 |
|---|---|
| 讲个人经历（面试、述职） | STAR（见 personal-effectiveness） |
| 向领导推销一个方案 | SCRTV（情境、冲突、原因、策略、价值）；时间紧时只讲“策略 + 价值” |
| 需要讲一个引人入胜的长故事 | 故事五要素、英雄之旅 |

## 金字塔的四个原则
1. **结论先行**：第一句话就是答案。
2. **以上统下**：上层观点是下层观点的概括。
3. **归类分组**：同一组观点属于同一类、同一抽象层次，而且 MECE。
4. **逻辑递进**：组内按时间、结构或重要性排序。

## 操作步骤
1. **写 SCQA 开头**：
   - 情境 S：听众都认同的背景
   - 冲突 C：出了什么问题或变化
   - 疑问 Q：因此要回答什么
   - 回答 A：我们的结论
2. **列出支撑论点**：通常 3 个左右，彼此 MECE。
3. **选择论证方式**：归纳（几个并列理由共同支撑结论）更适合汇报；演绎（大前提、小前提、结论）的风险是听众不同意大前提就全盘否定，而且要听到最后才知道结论。
4. **每个论点配上事实和数据**。
5. **做故事线检查**：只读每页（或每段）的标题，能否连成一个完整、有说服力的故事？
6. **初学者先用自上而下法**：先想结论，再找支撑；卡住时再用自下而上法，从材料中归纳。

## 输出模板
```
结论：……
S：……  C：……  Q：……  A：……
论点 1：……（依据：……）
论点 2：……（依据：……）
论点 3：……（依据：……）
建议行动：……
```

## 常见误用
- 按分析的过程讲，而不是按结论讲，听众要听到最后才知道你想说什么。
- 论点之间重叠，或者层次不一。
- 论点没有数据支撑，只有观点。
- 同一组放了七八条，没有进一步归类。
