# 管理咨询分析

这套 skill 的价值不在于背出框架定义，而在于**选对方法**。咨询顾问最常见的失败是把一堆框架硬套上去：每个框架都填满了，却没有回答决策者真正关心的问题。所以每次都先诊断，再选方法，最后只呈现能支撑结论的那部分分析。

## 和 management-toolkit 的分工

- 本 skill 回答“**企业该往哪走、为什么经营成这样**”：从外部视角诊断方向和业绩。
- management-toolkit 回答“**定好的事怎么做成、团队怎么带好**”：目标设定、执行改进、质量问题根因、复盘、团队与变革管理。
- personal-effectiveness 回答“我自己怎么更高效”：个人的时间、习惯、学习、决策和职业发展。
- 一个问题可能两边都涉及。例如“战略定了落不了地”：先用本 skill 的 7S 诊断卡在哪里，再用 management-toolkit 设计目标分解和变革推进。

## 工作流程

### 第一步：把问题说清楚

先用一句话写出“主导问题”。它应当具体、可行动，并以决策者下一步要做的决定为重点，而不是事实罗列或无可争议的口号。

- 差：“公司执行力有问题。”（这是症状，不是问题）
- 好：“华东区销售 Q3 未完成目标，是因为目标定得不合理，还是因为渠道覆盖不足？”

同时弄清六件背景事项：决策者是谁、他最关心什么、什么时候要答案、成功的标准、主要衡量指标、需要多高的精度。信息不够时，先向用户问最关键的一两项；问不到就写明你的假设，继续往下做。

### 第二步：判断问题类型，选方法

先按下表定位问题类型，再看前提条件是否满足。每次只选 **1 个主方法 + 最多 1 个辅助方法**，并在输出里说明“为什么用它、为什么不用相邻的那个”。

**A. 还不知道问题在哪**
| 情况 | 首选 | 何时换用 |
|---|---|---|
| 对情况了解很少 | 议题树 | 已有明确猜想就改用假设树 |
| 已有方向性判断，时间紧 | 假设树 | 假设被数据推翻就重建 |
| 指标可以用公式拆 | 公式法议题树（如利润 = 收入 − 成本） | 公式拆分天然满足 MECE，能用就优先用 |
| 多个方案要做决定 | 是否树（决策树） | 常在项目后段或向领导呈现选项时用 |

**B. 业绩问题**
| 典型问法 | 首选 | 何时换用 |
|---|---|---|
| “利润为什么下滑？” | 利润树（收入 = 量 × 价，成本 = 固定 + 可变） | 定位到收入侧后，看客户与竞争可接 3C；定位到成本侧，可接价值链或标杆分析 |
| “和同行比我们差在哪？” | 标杆分析 / 竞争态势矩阵（CPM） | 需要对标数据；拿不到数据时退回定性的 KSF 对比 |
| “财务上哪块出了问题？” | 杜邦分析 / 财务雷达图（收益性、安全性、流动性、生产性、成长性） | 只能看出结果，找原因要接利润树 |
| “成本太高怎么降？” | 价值链 + 零基预算 | 质量或流程浪费导致的成本，交给 management-toolkit 的精益方法 |

**C. 行业与市场**
| 典型问法 | 首选 | 何时换用 |
|---|---|---|
| “这个行业值不值得做？” | 波特五力 | 行业剧变时补 PEST 看趋势；想看冲击的传导，用 SCP |
| “外部环境变化对我们有什么影响？” | PEST / PESTEL | 只看宏观，要落到企业自身必须接 SWOT |
| “市场有多大？” | 市场规模估算（自上而下 + 自下而上交叉验证，TAM/SAM/SOM） | 两种算法差距大时，要解释原因，不能取平均了事 |
| “这个行业靠什么赢？” | 关键成功因素（KSF） | 对比成功者和失败者得出 |
| “未来不确定性很大，怎么准备？” | 情景规划 | 已识别出 2 个关键不确定因素时最有效 |

**D. 战略方向与增长**
| 典型问法 | 首选 | 何时换用 |
|---|---|---|
| “明年战略重点放哪？” | SWOT → TOWS 组合 | SWOT 只列清单不排序，必须接组合或加权打分（IFE/EFE） |
| “靠什么增长？” | 安索夫矩阵 | 想看更多增长途径时用“增长七个自由度”；要平衡长短期，用增长三层面 |
| “要不要进入这个市场？” | 市场进入框架：市场吸引力 → 我们的胜算 → 进入方式 → 财务测算 | 行业吸引力部分可以直接用五力 |
| “多条业务该投哪个、砍哪个？” | BCG 矩阵 | 因素更复杂时用 GE 矩阵；成熟市场看竞争地位可用三四规则 |
| “用什么方式竞争？” | 波特通用战略（成本领先、差异化、聚焦） | 想看价格与附加值组合用战略钟；想选定位方向用价值信条（运营卓越、产品领先、亲密客户） |
| “市场太挤，怎么突围？” | 蓝海战略（剔除、减少、增加、创造四步） | 需要对行业竞争要素了解透彻 |
| “商业模式要不要改？” | 商业模式画布 | 只描述模式，评估好坏还要结合五力或利润树 |
| “要不要收购这家公司？” | 并购框架：战略契合 → 标的质量 → 协同效应 → 估值 → 整合风险 | 纯合作不必控股时，考虑战略联盟 |

**E. 客户与营销**
| 典型问法 | 首选 | 何时换用 |
|---|---|---|
| “份额为什么被对手抢走？” | 3C（公司、客户、竞争对手） | 纯成本或运营效率问题不要用 3C |
| “该服务哪些客户？” | 客户细分 → STP（细分、选择目标、定位） | 细分维度要能测量、能触达、有利润差异 |
| “营销策略哪里有问题？” | 4P（产品、价格、渠道、推广） | 服务业可扩展为 7P |
| “该怎么定价？” | 定价三角：成本、竞品、客户价值（支付意愿） | 有数据时可做价格弹性或支付意愿调研 |
| “客户为什么不满意、为什么流失？” | 客户旅程分析 | 需要访谈或行为数据支撑 |

**F. 组织诊断**（只诊断“卡在哪”，推进变革交给 management-toolkit）
| 典型问法 | 首选 | 何时换用 |
|---|---|---|
| “战略定了为什么落不了地？” | 麦肯锡 7S | 7S 不看外部环境；需要快速、参与式诊断时用韦斯伯德六盒模型 |
| “要做大的组织变革，先改哪里？” | Burke-Litwin 模型 | 需要看清因果和变革先后顺序时用 |
| “有哪些人会支持或反对？” | 利益相关者分析（影响力 × 态度） | 常与其他方法搭配使用 |

**G. 呈现结论**：一律用 SCQA 开头、金字塔原理展开，见第四步。

找不到合适的现成框架时，按“自下而上”的方法建结构：把所有想法列出来，把相近的连线分组，给每组起标题，再检查组与组之间是否 MECE。不要为了用框架而削足适履。

每个方法的适用条件、局限和出处，请查 `references/method-index.md`；需要深入使用时，再读 `references/methods/` 下的方法卡片。

### 第三步：做分析

- **假设驱动**：先给出一个初步答案，再去找证明或推翻它的事实。假设被推翻很正常，要及时改。
- **以事实为依据**：每个论点都要有数据或事实支撑。缺数据时写明“这是推断”，并说明需要什么数据来验证。
- **80/20**：只深挖对结论影响最大的几个分支，其余明确写“暂不展开”。
- **够精确就好**：商业决策不需要科学级精度，方向正确比小数点重要。

### 第四步：呈现结论

默认输出汇报格式，因为结论最终要给别人看：

```
## 结论（一句话，先说答案）

## 背景（SCQA）
- 情境 S：大家都认同的现状
- 冲突 C：出了什么问题 / 出现了什么变化
- 问题 Q：因此要回答的问题
- 答案 A：我们的建议

## 支撑论点（3 个左右，彼此 MECE）
1. 论点一：……（事实/数据：……）
2. 论点二：……
3. 论点三：……

## 建议的行动（谁、做什么、何时完成、如何衡量）

## 分析方法说明
- 用了什么方法，为什么选它；为什么没用相邻的方法
- 哪些结论是推断，需要什么数据验证
```

如果用户只是自己想把问题想清楚，可以省去 SCQA 包装，直接给议题树或分析表，最后再给结论。

## 几条底线

- 结论先行：第一句话就是答案。
- 以上统下：上层观点必须是下层观点的概括；同一组内的观点必须同类、同一抽象层次。
- 不要把“其他”放在最高层级。
- 方法说明要诚实：某个框架对这个问题帮助不大，就直说，不要为了显得全面而硬填。
