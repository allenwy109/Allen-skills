# 方法卡片：根因分析（鱼骨图 + 5WHY）

## 它解决什么问题
一个已经发生的问题（不良率高、客户投诉、项目延期），要找到真正的原因，而不是只处理表面现象。

## 怎么选
| 你的处境 | 用哪个 | 原因 |
|---|---|---|
| 现象清楚，原因大概只有一个，链条清晰 | 直接用 5WHY | 快，一条链追到底 |
| 原因可能有很多，涉及多个环节、多个部门 | 先用鱼骨图，再对主要原因用 5WHY | 鱼骨图保证广度，5WHY 保证深度 |
| 质量或客诉问题，需要先止损再根治，并防止复发 | 用 8D 串起来，D4 这一步用鱼骨图 + 5WHY | 需要闭环和团队协作 |

## 不适用的情况
- 问题还没发生，要预防风险：用 FMEA 之类的风险分析，不是根因分析。
- 战略层面的问题（如“份额为什么下滑”）：因素之间相互影响，鱼骨图容易变成一张清单；应改用 consulting-analysis 的议题树或 3C。

## 操作步骤
1. **描述问题**：用 5W2H 写清楚现象，要让不熟悉情况的人也能看懂。形容词（大、慢、多）要写明和什么比。
2. **鱼骨图铺开**：选大骨。制造或质量问题用 5M1E（人、机、料、法、环、测）；管理问题可用人员、流程、制度、工具、信息、环境。每根大骨下列出可能原因。
3. **筛选**：用数据或团队共识选出 3～5 个主要原因（资料建议 4～6 个），不要全部深挖。
4. **5WHY 深挖**：对每个主要原因连续追问“为什么”。每个回答用“主语 + 谓语”的形式写成事实，而不是笼统的“管理不到位”。一直问到能提出防止再发的对策为止，次数不一定是 5 次。
5. **验证**：每个根因都要回到现场或数据检验：去掉这个原因，问题是否会消失？
6. **对策**：区分临时措施和根本措施，写清负责人和期限。

## 输出模板
```
问题描述：……（何时、何地、多少、与什么标准相比）

鱼骨图（可能原因）
- 人：……
- 机：……
- 料：……
- 法：……
- 环：……
- 测：……

主要原因与 5WHY
原因 A：为什么 1 → …… → 为什么 n → 根因：……（验证方式：……）
原因 B：……

对策
| 根因 | 临时措施 | 根本措施 | 负责人 | 期限 |
```

## 常见误用
- 一开始就用 5WHY，只沿自己最先想到的那条链追下去，漏掉其他原因。
- 追到“员工不认真”“意识不够”这种无法采取对策的结论就停了。
- 鱼骨图画完就结束，没有用数据验证哪个才是真正原因。
- 把分析变成追责，大家不说真话。

## 资料之间的分歧
《问题分析与解决8大方法》说 WHY-WHY“适用于人的问题，最多不要超过 4 个提问”；《5WHY分析法（65P）》则要求追问到可以防止再发为止。这里采用后者：次数不是重点，能落到可执行的对策才是。

资料：《5WHY分析法（65P）》《5个为什么分析与鱼骨图分析讲义》《鱼骨图分析法》2 个文件、《精益生产之5M1E分析法》《问题分析与解决8大方法与工具》。补充：公开资料普遍认为 5WHY 一次只能找到一条因果链，复杂问题应与鱼骨图配合使用。
