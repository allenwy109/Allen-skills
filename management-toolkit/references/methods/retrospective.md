# 方法卡片：复盘（GRAI 四步法与 AAR）

## 它解决什么问题
一件事做完之后，把经验和教训提炼出来，让下一次做得更好，把经验转化为能力。

## 什么时候用
| 情况 | 用哪个 |
|---|---|
| 项目、活动或阶段结束，需要正式、深入的复盘 | 复盘四步法（GRAI） |
| 会议、日常活动结束后的快速总结 | 非正式 AAR（5 分钟） |
| 重要行动后的正式反思，有外部观察者 | 正式 AAR |

## 什么时候不用，或换用什么
- 要解决一个具体的质量问题：用 8D 或 PDCA。AAR 和 PDCA 功能不同，不能互相替代。
- 目的是追究责任：那就不是复盘了，大家也不会说真话。

## GRAI 四步
1. **回顾目标（Goal）**：当初的目的和目标是什么？先检查目标本身有没有定错。
2. **评估结果（Result）**：与目标对比，有哪些亮点、哪些不足？亮点和不足同样重要。
3. **分析原因（Analysis）**：成功的关键因素是什么？失败的根本原因是什么？多从自身找原因。
4. **总结规律（Insight）**：学到了什么？下次怎么做？总结规律要谨慎，不能把一时一地的经验当成普遍规律。

## AAR 四个问题
1. 我们原本预期发生什么？
2. 实际发生了什么？
3. 为什么会有差异？
4. 下次我们怎么做？（保持什么、改进什么）

## 操作步骤
1. 尽早复盘，趁记忆清晰。
2. 让所有关键参与者到场，负责人先带头反思自己。
3. 指定一个引导者，控制节奏，确保每个人都发言。
4. 按四步走，记录要点。
5. 把行动项落实到人和时间，下次行动前回看。

## 输出模板
```
| 步骤 | 内容 |
|---|---|
| 目标 | 当初的目标 ……；目标是否合理 …… |
| 结果 | 亮点 ……；不足 …… |
| 原因 | 成功因素 ……；失败原因 …… |
| 规律 | 学到 ……；下次 ……（负责人、时间） |
```

## 常见误用（资料总结的五个误区）
- 为了证明自己对。
- 流于形式，走过场。
- 变成追责大会。
- 只谈现象，不找根本原因。
- 总结出一堆“规律”，其实只是这一次的特例。
